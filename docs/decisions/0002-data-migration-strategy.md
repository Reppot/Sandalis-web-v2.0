# ADR-0002: Стратегия миграции данных из Supabase в PostgreSQL 16

## Статус
Принято

## Контекст
Старый проект хранит данные в Supabase PostgreSQL через Transaction Pooler (:6543, pgbouncer).
В новой архитектуре мы переходим на нативный PostgreSQL 16 на render.com — это устраняет
зависимость от Supabase и снимает ограничения бесплатного тарифа.

## Решение
1. **Скрипт `migrate_from_supabase.py`** переносит все таблицы: users, sessions, orders,
   order_items, stockpiles, stockpile_items, timers.
2. **Скрипт идемпотентен:** повторный запуск не создаёт дубликатов — проверка по PK/уникальным полям.
3. **UUID сохраняются:** переносим `id` как есть, чтобы не ломать ссылки в сессиях Discord и старых экспортах.
4. **Только активные сессии:** переносим `sessions WHERE expires_at > NOW()`.
5. **Пропускаем миграции схемы:** таблицы создаются через `alembic upgrade head` из ADR-0001.
6. **Формат подключения:** переменные `SOURCE_DB_URL` (старая БД) и `DATABASE_URL` (новая).

## Последствия
- Одноразовый запуск в момент cutover перед сменой DNS.
- Ноль потери данных пользователей и складов клана.
- После успеха Supabase-инстанс можно погасить.
