# ADR-0001: Структура монорепозитория и выбор версий

## Статус
Принято

## Контекст
Старый проект Sandalis-Web — монолит Next.js без бэкенда.
Необходима пересборка с выделением Python-бэкенда и чистой
модульной архитектуры фронтенда.

## Решение
1. Монорепозиторий `sandalis/` с тремя рабочими папками:
   `frontend/`, `backend/`, `infra/`.
2. Frontend фиксируется на Next.js 15.x (последний стабильный App Router,
   React 19). Когда Next.js 16 выйдет в stable — обновляется одна строка
   в package.json.
3. Backend — FastAPI + SQLAlchemy 2 async + asyncpg.
4. Данные (каталоги, иконки, видео) хранятся в PostgreSQL и S3.
   В git — только код.
5. Три репозитория GitHub: исходник (read-only), прокладка-трекер (план),
   результат (этот код). Код пишется только в результат.

## Последствия
- Верхнеуровневая структура зафиксирована (раздел 4 промпта).
- Нижнеуровневые файлы внутри папок растут свободно.
- Render.com Blueprint (`infra/render.yaml`) деплоит всё одной кнопкой.
