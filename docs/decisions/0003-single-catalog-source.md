# ADR-0003: Единый источник каталога предметов

## Статус
Принято

## Контекст
В старом проекте номенклатура Foxhole была размазана по трём файлам:
- `src/lib/factory-data.ts` (120 922 Б) — рецепты фабрик
- `src/lib/item-catalog.ts` (59 731 Б) — русские названия
- `src/lib/itemCodes.ts` (56 900 Б) — коды предметов
- `src/lib/item-icon-overrides.ts` — оверрайды иконок

Итого ~240 КБ TypeScript кода с дублирующимися записями. При каждом добавлении
предмета приходилось править три места, что приводило к рассинхронизации.

## Решение
1. Все четыре источника **объединяются в одну таблицу PostgreSQL `items`** с полями:
   `id, code, name, english_name, category, icon_url, crate_size, production_time`.
2. Рецепты фабрик — в отдельной таблице **`recipes`** со связью `item_id` и JSON-полем
   `ingredients` (упрощает добавление новых типов ингредиентов).
3. Импорт выполняется скриптом `scripts/import_catalog.py`:
   - Читает `catalog.json` (структурированные метаданные).
   - Опционально извлекает рецепты из `fs_vanilla.h5` через h5py.
   - Идемпотентен: обновляет существующие записи, добавляет новые.
4. Фронтенд запрашивает предметы через `GET /api/v1/items?q=&category=`.
   Никакого хардкода в JS.

## Последствия
- Из фронтенд-бандла удалено 240 КБ статики.
- Обновление номенклатуры не требует redeploy фронта.
- Единственный источник правды по номенклатуре: PostgreSQL.
