# ADR-0004: AI-снимки кода — только как CI-артефакты

## Статус
Принято

## Контекст
В старом проекте post-commit git-хук на каждый коммит генерировал файлы
`SNAP_1.md`, `SNAP_2.md`, `SNAP_3.md`, `SNAP_4.md` с полным дампом кода
для скармливания ИИ. Также существовали:
- `PROJECT_INGEST.md` (446 КБ) — единый ingest-файл
- `all_files_paths.txt` (3 029 858 Б) — список всех путей
- `README.md` (154 КБ) — переросший в свалку контекста

Проблема: репозиторий распухал на десятки мегабайт текстовых артефактов, история
git становилась нечитаемой (`git log --stat` захлёбывался).

## Решение
1. Все `SNAP_*.md`, `PROJECT_INGEST.md`, `all_files_paths.txt` **удалены из git**
   и добавлены в `.gitignore`.
2. Снимок кода собирается **GitHub Actions workflow** `ai-snapshot.yml` на каждый push в main.
3. Артефакт хранится 30 дней и скачивается по ссылке из вкладки Actions в GitHub.
4. `README.md` сведён к 80 строкам: назначение, стек, quickstart, ссылки на ADR.

## Последствия
- Репозиторий больше не растёт от коммита к коммиту.
- История git снова читаема.
- Контекст для ИИ доступен по требованию, а не засоряет исходники.
- README перестал быть свалкой.
