# Генератор руководства «Навигация»

Генератор снимает актуальный интерфейс терминала на русском и английском языках, проверяет, что поясняемые элементы попали в кадр, и записывает чистые скриншоты без наложенных меток:

- `backend/static/guide/<locale>/<shot>.<hash>.webp` — изображения экранов. Хэш в имени обновляет URL при каждом новом кадре и обходит недельный HTTP-кэш;
- `backend/app/seed/data/guide.json` — главы, подписи и пояснения рядом со скриншотами.

Существующие локали помимо русского и английского сохраняются без изменений. Тексты и сценарии снимков находятся в `chapters.mjs`, демо-данные — в `demo.mjs`. После успешного создания всех кадров генератор удаляет неиспользуемые `.webp` только из папок `ru` и `en`.

## Изолированный запуск на Windows

Требуется запущенный Docker Desktop. Стенд использует отдельный Compose-проект `sandalis-guide`, PostgreSQL на `127.0.0.1:55433`, API на `127.0.0.1:8020` и веб-сайт на `127.0.0.1:3300`. Он не подключается к `infra-db-1` на порту 5432. Отдельная база `sandalis_test` создаётся только внутри контейнера Sandalis и предназначена для тестов, которые очищают свои таблицы.

Из корня репозитория:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\guide\start-demo.ps1
```

Откройте [http://127.0.0.1:3300](http://127.0.0.1:3300). Проверка backend:

```powershell
Invoke-WebRequest http://127.0.0.1:8020/api/v1/health/live
```

Чтобы остановить только этот стенд, не удаляя его данные:

```powershell
docker compose -p sandalis-guide -f .\infra\docker-compose.guide.yml down
```

Не добавляйте `-v`: named volume `sandalis-guide-pg` хранит изолированные данные стенда.

## Backend-тесты на отдельной базе

После запуска стенда:

```powershell
$env:TEST_DATABASE_URL = "postgresql+asyncpg://sandalis:sandalis-guide-local@127.0.0.1:55433/sandalis_test"
Push-Location .\backend
.\.venv\Scripts\python.exe -m pytest
Pop-Location
```

Тесты откажутся запускаться, если `TEST_DATABASE_URL` совпадает с `DATABASE_URL` приложения. Фикстуры очищают таблицы только в `TEST_DATABASE_URL`.

## Обновление снимков

Установите зависимости генератора один раз и запускайте из PowerShell:

```powershell
Push-Location .\tools\guide
npm ci
node .\generate.mjs
Pop-Location
```

По умолчанию используется Edge в `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`. Можно задать `GUIDE_FRONTEND`, `GUIDE_BACKEND` и `GUIDE_BROWSER`. При ошибке генератор сохраняет `debug-<locale>-<shot>.png` рядом со скриптами.

Генератор изменяет только снимки RU/EN и `guide.json`, сохраняя другие локали. После проверки эти файлы нужно включить в коммит — production backend раздаёт их из `backend/static/guide`.

Docker API хранит снимки и JSON внутри образа, поэтому после генерации пересоберите только API. При старте он повторно запустит сид и обновит локальный каталог глав:

```powershell
docker compose -p sandalis-guide -f .\infra\docker-compose.guide.yml up -d --build api
```

## Проверка руководства в браузере

После обновления demo API запустите:

```powershell
Push-Location .\tools\guide
npm run verify
Pop-Location
```

Проверка проходит все 18 глав на русском и английском, показывает по одному кадру, переключает кадры главы, проверяет примечания без маркеров поверх изображения и гарантирует, что скриншот не увеличивается выше исходного разрешения. Для длинного кадра проверяется прокрутка в увеличенном просмотре. На ширине 390 px проверяются оглавление, отсутствие переполнения, пустой обзор планирования, выбор двух регионов, ограничение данных выбранными гексами, сворачивание фильтров и кадрирование карты. Линия фронта должна быть сплошной сглаженной кривой, а переходы между её точками — короче трёх ширин гекса.

## Новое пояснение к снимку

Добавьте `data-guide="<id>"` нужному элементу и запись в массив `notes` снимка в `chapters.mjs`. Поле `sel` задаёт CSS-селектор для проверки присутствия цели в кадре; `note` содержит текст, который показывается отдельной карточкой рядом со скриншотом. Координатные метки поверх интерфейса не используются.
